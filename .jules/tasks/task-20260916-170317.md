Co-SMOS v0.9 — Consult Auth with Role-Based Access Control (RBAC)

CONTEXT:

- Spec: Co-SMOS v0.9 §9, §14, §25

GOAL:
Add role-based auth for /api/consult/* and write endpoints.
Three roles: consultant, operator, admin.
External AI consultants (e.g., DeepSeek) MUST be consultant only.

REQUIREMENTS:

1. TOKENS
Read three tokens from environment variables:
- JULES_CONSULTANT_TOKEN  (default: "dev-consultant-token")
- JULES_OPERATOR_TOKEN    (default: "dev-operator-token")
- JULES_ADMIN_TOKEN       (default: "dev-admin-token")

If all three are default, log a warning once at startup.
Do NOT hardcode real secrets in source.

2. ROLE RESOLUTION
- Parse Authorization: Bearer <token>.
- Resolve role by matching token against the three env values.
- Use hmac.compare_digest for all comparisons.
- If no match: 403 CONSULT_AUTH_INVALID.
- If header missing/malformed: 401 CONSULT_AUTH_REQUIRED.

3. ROLE PERMISSIONS
- consultant: GET /api/consult/* only.
- operator:   consultant + POST /api/tasks, PATCH /api/tasks/{id},
              POST /api/proposals, POST /api/proposals/{id}/accept,
              POST /api/batch/run.
- admin:      operator + configuration endpoints (if any).

4. ENDPOINT MATRIX
GET /api/consult/state         -> consultant, operator, admin
GET /api/consult/tasks         -> consultant, operator, admin
GET /api/consult/task/{id}     -> consultant, operator, admin
GET /api/consult/events        -> consultant, operator, admin
GET /api/consult/errata        -> consultant, operator, admin
GET /api/consult/health        -> consultant, operator, admin
                                  (or public with ?public=1)
POST /api/tasks                -> operator, admin
PATCH /api/tasks/{id}          -> operator, admin
POST /api/proposals            -> operator, admin
POST /api/proposals/{id}/accept-> operator, admin
POST /api/batch/run            -> operator, admin

5. SAFETY
- consultant MUST NOT be able to POST/PATCH/PUT/DELETE anything.
- All write attempts by consultant -> 403 CONSULT_ROLE_FORBIDDEN.
- Anonymous write attempts -> 401 CONSULT_AUTH_REQUIRED.
- Use constant-time compare (hmac.compare_digest).
- Do NOT log token values.
- Do NOT store tokens in localStorage (frontend).

6. ERROR FORMAT
Canonical error responses:
  {status: "error", code: "...", message: "...", exit_code: null}
HTTP status must match:
  401 for missing/malformed
  403 for invalid token or insufficient role
  429 for rate-limited
