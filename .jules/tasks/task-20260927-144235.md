============================================================
CANONICAL FOUR-POSITION SEMANTICS
============================================================

The tests MUST use these meanings:

I — PRESENT_EXISTS
    "What would exist / happen if H exists?"

II — ABSENT_ABSENT
    "What would NOT exist / happen if H does not exist?"

III — ABSENT_EXISTS
    "What would exist / happen if H does not exist?"

IV — PRESENT_ABSENT
    "What would NOT exist / happen if H exists?"

These are INDEPENDENT analytical projections.

============================================================
CRITICAL TESTING PRINCIPLE
============================================================

The test MUST verify SEMANTIC INDEPENDENCE, not textual difference.

FORBIDDEN:
    assert claim_I != claim_III
    assert claim_II != claim_IV
    assert inverse(claim_I) != claim_III

REASON:
    Two positions MAY legitimately contain the same claim in some
    domain situations. The test must not enforce artificial textual
    inequality.

INSTEAD:
    Provide fixture evidence where the semantic distinction is
    OBSERVABLE. For example:

        I:   H exists  -> X increases
        III: H absent  -> Y remains active
        where X and Y are DIFFERENT domain entities

    The test proves independence by demonstrating that III is not
    derived from I by mechanical negation.

       PRESENT_EXISTS
       ABSENT_ABSENT
       ABSENT_EXISTS
       PRESENT_ABSENT

Use TASK 24 normalization/validation helpers where available.

TEST 2 — FOUR QUESTIONS REMAIN DISTINCT
============================================================

The fixture SHOULD provide evidence that makes these distinctions
observable.

TEST 4 — BLOCKAGE IS NOT ABSENCE CONSEQUENCE
============================================================

Create evidence representing:

    "H is blocked by constraint C."

Verify that this does NOT automatically become:

    "If H does not occur, X will not occur."

The test MUST preserve the semantic distinction:

    BLOCKAGE
        = condition preventing H

    versus:

    ABSENT_ABSENT
        = consequence that does not occur because H is absent

A blockage relation MAY provide evidence relevant to a position, but
the service MUST NOT silently reinterpret the relation as a
counterfactual consequence.

This is a SEPARATE semantic test, not a textual check.
