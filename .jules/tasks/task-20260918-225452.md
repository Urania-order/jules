Co-SMOS v1.2.1 — Admin UI: Queue-based task submission + Run Next

CONTEXT:
- Repo: Urania-order/jules
- Backend: smos/api/main.py (already has POST /api/admin/run)
- Frontend: frontend/index.html (view-admin with admin-command, admin-args, admin-run)

- Existing: scripts/run-task.sh — full cycle for ONE file
  - accepts any path (verified: TASK_FILE=$1, cat "$TASK_FILE")
  - compatible with running/admin-*.txt
- User wants: in Admin UI, submit task text -> queue -> run next from queue

GOAL:

1. Backend: new endpoints in smos/api/main.py

   a) POST /api/admin/queue/add
      - Body: {text: str, verify_task: Optional[str]}
      - Writes .jules/queue/pending/admin-<uuid8>.txt
        Content: task text (raw prompt)
      - Optional sidecar: .jules/queue/pending/admin-<uuid8>.meta.json
        {"verify_task": "11", "created_at": "...", "by": "operator"}
      - Response: {queued: true, filename: "admin-<uuid8>.txt"}
      - Auth: operator/admin

   b) POST /api/admin/queue/run-next
      - Picks OLDEST .txt from .jules/queue/pending/
      - If none: 400 {error: "next_task_not_formed", message: "No pending task files"}
      - If found:
        * Move to .jules/queue/running/<same-name>
        * Read sidecar meta (if exists) for verify_task
        * Run: ./scripts/run-task.sh <running-file> [--verify <verify_task>]
        * On success (exit 0): move to .jules/queue/completed/
        * On failure: keep in running/ + append error to .jules/queue/runner.log
      - Response: {dispatched: true, filename, task_id, exit_code, duration_ms}
      - Timeout: 1200s (20 min)
      - Auth: operator/admin
      - Audit log (both success and rejection):
          .jules/history/admin_audit.jsonl

   c) GET /api/admin/queue/list
      - Response: {pending: [...], running: [...], completed: [...]}
        Each: {filename, size, created_at}
      - Auth: operator/admin

2. Frontend: view-admin -> New Task section

   Layout:
   ┌─ Queue Status ─────────────────────┐
   │ Pending:   N files                  │
   │ Running:   N files                  │
   │ Completed: N files                  │
   └─────────────────────────────────────┘

   ┌─ New Task ─────────────────────────┐
   │ Prompt:      [textarea]             │
   │ Verify Task: [input, optional]      │
   │                                     │
   │ [📥 Add to Queue]  [▶ Run Next]     │
   └─────────────────────────────────────┘

   Behavior:
   - [📥 Add to Queue]:
       * If textarea empty -> showError("Prompt is empty")
       * Else POST /api/admin/queue/add
       * On success: clear textarea, refresh queue status, toast "Added: admin-abc123.txt"
   - [▶ Run Next]:
       * POST /api/admin/queue/run-next
       * If 400 next_task_not_formed:
           - showError("Наступне завдання не сформовано")
           - Highlight textarea (focus + red border briefly)
       * If success: refresh queue status, show output in admin-output
   - Queue status auto-refresh every 10s (or on action)
