## Request

Co-SMOS v1.1.6 — Task metadata: created_at + proposed_by in scripts

CONTEXT:
- Repo: Urania-order/jules
- Root cause: scripts/jules-task.sh (line ~104) writes only {id, request}
  into state["active_task"]. Other fields are not written.
- scripts/jules-complete.sh (line ~246) builds `completed` manually
  and copies active.get("started_at"), active.get("branch"), etc.
  But active_task has only {id, request} → all those become null.
- Result: all tasks in state.json have:
    * created_at: null
    * proposed_by: null (author)
    * title: null
    * priority: null
    * started_at: null
- Side effect: scripts/jules-queue-runner.sh:128 already sorts by
  `item[1].get("created_at", "")` — but created_at is always "" → no sort.

- Pydantic Task model (smos/core/task.py:29) ALREADY HAS these fields:
    * created_at (auto-gen via datetime.now(timezone.utc))
    * proposed_by (author)
    * title, priority, started_at, finished_at, source_task
- smos/core/queue.py:42-55 already reads these fields with fallback.
