FOUR-POSITION ANALYSIS SERVICE

============================================================
PURPOSE
============================================================

Implement the read-only service that projects the canonical

This service is an ORCHESTRATION / PROJECTION layer.

It is NOT a new reasoning engine.

It MUST NOT invent conclusions that are not supported by canonical
evidence.

============================================================

============================================================

Before implementation inspect:

CRITICAL:
Do NOT assume that an existing service corresponds directly to a

the Four-Position semantics.

============================================================
CANONICAL FOUR-POSITION CONTRACT
============================================================

For hypothesis/phenomenon H:

Position I — PRESENT_EXISTS
    Question: "What would exist / happen if H exists?"
    Represents positive consequences or states associated
    with H being present.

Position II — ABSENT_ABSENT
    Question: "What would NOT exist / happen if H does NOT exist?"
    Represents consequences that disappear specifically
    because H does not occur.
    IMPORTANT:
    BlockageAnalysisService is NOT automatically equivalent to
    this position.
    - Blockage describes what prevents H.
    - Position II describes what does not occur when H is absent.
    These are DIFFERENT statements.

Position III — ABSENT_EXISTS
    Question: "What would exist / happen if H does NOT exist?"
    Represents the baseline, alternative state, alternative
    process, or alternative phenomenon that exists when H does
    not occur.
    Current context MUST NOT automatically be treated as the
    complete counterfactual alternative.

Position IV — PRESENT_ABSENT
    Question: "What would NOT exist / happen if H exists?"
    Represents consequences, alternatives, processes, states, or
    possibilities displaced, prevented, or made unnecessary by H.
    EmergenceAnalysisService MUST NOT automatically be treated as
    a source for this position unless STEP 0 confirms that it
    provides canonical displacement/suppression evidence.

============================================================
CORE ARCHITECTURAL RULE
============================================================

The service MUST NOT implement:

    I   = Emergence
    II  = Blockage
    III = Context
    IV  = Emergence suppression

as a hard-coded semantic equivalence.

Instead:

    FourPositionService
        |
        v
    selects/maps existing canonical evidence
        |
        v
    into the four canonical projections.

Existing services are EVIDENCE PROVIDERS, not definitions of the
Four-Position semantics.

============================================================

CRITICAL:
