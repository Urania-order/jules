2.8 Cross-verify two-object identity vs ID reuse

CRITICAL — h0.id == p_core.id does NOT prove collision.

Within one table, SQLite cannot hold two rows with the
same primary key simultaneously.

If two Python objects have the same id value, one of
the following is true:

    (a) ID reuse — one row was DELETED (or rolled back),
        then a new row was inserted with the same
        auto-increment value (unusual in SQLite unless
        reset happened)

    (b) Stale Python object — one of the Python objects
        references a row that no longer exists in the
        table

    (c) Both rows exist with different PKs in the table,
        but Python objects refer to the same id by
        accident (e.g. one object references a wrong id)

    (d) Both rows exist simultaneously with the same
        id (impossible in a healthy table)

Jules MUST determine which of (a)-(d) applies, using
the debug test from 2.7 at multiple positions.

Required observations:
    - count rows in phenomena table where id == 11
    - count rows in phenomena table where id == p_core.id
    - count rows in phenomena table where id == h0.id
    - verify whether both rows exist simultaneously
    - verify the phenomena table has unique PK constraint
    - check sqlite_sequence for phenomena table

Record ACTUAL observations.
